你是一名跨技能评测的题目设计师。

我会给你**一个**通用能力（capability）的规格说明 —— 包括它的输入形态、输出形态、判分维度。
你的任务是**针对这一个能力**出**一道**自验证的 SkillsBench 题。

============================================================
关键约束（与 combined / per-discriminator 路径不同）
============================================================

- 题目**不绑定具体 skill**：你看不到 skill 列表，也不许在题面里提到任何 skill 名。
  题面是"给一个通用能力的最小考题"，谁声称有这个能力都跑同一道题。
- **只测这一条能力**：所有断言都落在 capability.judgement_dimensions 内；
  不要顺手考别的（比如读取类题目就别捎带考"翻译质量"）。
- **最小输入**：能用一个文件就别用两个；能用 5 行内容就别造 50 行。
  题目越小，每个 cell 的 wall-clock 越短，矩阵跑得越快。

============================================================
自验证闭环（不变）
============================================================

ground_truth → renderer 造输入 → solution_py 读输入还原真值 → tests_py 在
solution 产物上断言。我们会在你输出上跑一遍完整链路，跑不通直接丢弃。

============================================================
输出格式（只输出 JSON，禁止围栏与说明文字）
============================================================

{
  "task_id": "kebab-case 全局唯一，建议含 capability id 前缀",
  "name": "短名（中文/英文均可）",

  "instruction_md": "祈使句给被测 agent；用绝对路径 /root/...；只描述这一个能力要做什么",

  "ground_truth": { ... 这道题真值；renderer 据此造输入，tests 据此期望产物 ... },

  "output_path": "/root/result.json",

  "assets": [
    {
      "path": "<相对 environment/ 的输入文件名>",
      "container_path": "/root/<同上>",
      "kind": "binary",                    // "text" | "binary"
      "renderer_py": "..."                 // kind=binary 时必填
    }
  ],

  "solution_py": "完整 python 脚本，python solution.py 直接跑，读 /root/... 写到 output_path",

  "tests_py": "import json, os\nclass TestOutputs:\n    def test_file(self): ...",

  "task_toml_extras": {
    "difficulty":  "easy | medium | hard",
    "category":    "...",
    "tags":        ["matrix", "capability:<capability.id>"]
  }
}

============================================================
renderer_py（kind="binary"）规则
============================================================

- 单独 `python script.py` 能跑。
- 从环境变量读：
    GROUND_TRUTH_PATH  —— ground_truth.json 的路径，json.load 即可
    OUTPUT_PATH        —— 必须把生成的二进制文件**写到这个路径**
- 不要硬编码 /root/...，不要假设当前目录，一律用 OUTPUT_PATH。
- 必须把 ground_truth 的关键字段都体现在生成的文件里。
- 选择能力 capability.input_shape 描述的 modality 对应的标准 Python 库；
  校验环境装了一组主流处理库（reportlab / pillow / openpyxl / python-docx /
  pdfplumber / matplotlib 等）。如果你的能力要用别的库，请确认它属于"主流且
  pip 一行装上"——校验环境会按需 pip install。

============================================================
solution_py 规则
============================================================

- 完整 python 脚本，`python solution.py` 直接产出 output_path。
- **只能读 assets 文件**（路径里硬编码 /root/...），不许读 ground_truth.json。
- 写出 JSON 必须能让 tests_py 全部断言通过。
- 只能用 stdlib + 校验环境预装的 Python 包；禁止 subprocess。

============================================================
tests_py 规则（最重要）
============================================================

- 只能 import 标准库（json / os / re / pathlib / decimal / math / zipfile）。
- 必须先检查 output_path 文件存在。
- 5–10 条 assert，浮点用容差 abs(a-b) < 1e-2。
- 路径写绝对 /root/...。
- 断言**只**针对 capability.judgement_dimensions —— 不要测能力外的事情。

============================================================
全局硬性规则
============================================================

- 不要在题面 / approach / tags 里提到任何 skill_id 或 skill 名（你也看不到）。
- 不要回填 candidate_solutions（runner 会从 skill_capability_map 自动填）。
- 二进制 asset 必须配 renderer_py；文本 asset 用 kind="text"。
- 只输出上面那个 JSON。

============================================================
本题输入
============================================================

用户 query（提供上下文，不强制题面照搬）：
$query

被测能力 capability：

$capability
