常见修复模式（按阶段对应）
============================================================

**tests 阶段失败（pytest exited 5 = no tests ran）**：
- 原因：你把测试写成了模块顶层的 `def test_xxx()` 但里面包含模块级 assert / 顶层执行代码，
  或干脆没写以 `test_` 开头的函数。
- 修复：所有断言**必须**放在以 `test_` 开头的函数体内，或包在 `class TestX:` 里的 `test_` 方法里。
  不要在模块顶层执行业务逻辑（不要在文件顶层 open 文件、跑 assert、读 result.json）。
  正确骨架：
      import json, os
      class TestOutputs:
          def test_file_exists(self):
              assert os.path.exists('/root/result.json')
          def test_value(self):
              d = json.load(open('/root/result.json'))
              assert d['foo'] == 'bar'

**tests 阶段失败（assertion 在 collection 阶段触发）**：
- 你在模块顶层就调用了 `os.listdir(...)` 之类的代码，pytest 还没跑测试就崩了。
- 修复：把所有这类调用挪进 test_ 函数体内。

**tests 阶段失败（pytest exited 1 = 真实断言失败）**：
- solution 的产物确实不满足 tests 的期望。
- 修复：调整 solution_py 让它产出符合 tests 期望的值；或松动 tests 的浮点容差。
  不要为了通过测试而把 tests 改弱（删断言、把数值改大）。

**solution 阶段失败**：
- 如果是 ModuleNotFoundError：换一个校验环境已有的库实现（pypdf/pdfplumber/pdfminer.six/
  reportlab/python-docx/pytesseract/Pillow 这些都已预装）。
- 如果是 regex / 解析逻辑错：修 solution_py，让它正确读出 ground_truth 期望的字段。

**render 阶段失败**：
- renderer_py 没把文件写出来，或写错了路径。
- 修复：确认 renderer 用环境变量 OUTPUT_PATH 写文件，不要硬编码 /root/...。
